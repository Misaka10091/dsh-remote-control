# 面板接入地址与模态重做

## 背景

设备面板上线后暴露三个问题（2026-10-19，真实 GUI 截图）：

1. **被遮挡**：面板是锚定弹层（`.drc-panel{position:absolute;bottom:calc(100% + 8px)}`），挂在侧栏底部的 seat 里，被侧栏的 `overflow` 裁掉右侧与底部，内容看不全。
2. **地址不可选**：配对链接的主机名取自**页面自身**（`pairingUrl()` 用 `document.baseURI` 的 hostname），桌面端在本机打开时永远是 `127.0.0.1`，面板只能给一条「请自己把 127.0.0.1 换成局域网 IP」的提示（`pair.loopbackHint`）。上一阶段的 `design.md` §7 只承诺了「局域网地址展示与可达性提示」，公网明确列为非目标（`prd.md` §范围），所以这条一直是手工活。
3. **失焦即消失**：点面板外任意位置就关闭，误触成本高。

## 目标

1. 面板以**居中模态弹窗**呈现：完整可见、不被任何祖先容器裁切、不因鼠标移到别处而消失。
2. 配对链接的主机名由**用户选定的接入地址**决定，而不是页面自身的地址。
3. 支持两类接入地址：
   - **局域网**：从本机网卡枚举出的 IPv4 里选择；
   - **公网**：用户**自行配置，且可配置多条**（例如家里 DDNS、公司域名、Cloudflare Tunnel 域名、公网 IP:端口），面板里切换当前使用的那条。
4. 不改变安全模型：网关仍绑 `0.0.0.0:<remotePort>`，管理 API 仍仅回环，**不内置穿透、不探测可达性**。

## 范围

| # | 能力 | 说明 |
|---|---|---|
| R1 | 模态弹窗 | 居中、带遮罩、显式关闭按钮 + `Esc`，**点遮罩不关闭**；打开时焦点进入面板，关闭后回到触发按钮 |
| R2 | 局域网地址选择 | 主机枚举非回环 IPv4，下拉选择；默认取第一条私网地址 |
| R3 | 多公网地址 | 可新增/删除多条公网地址（带可选备注名），单选一条作为当前地址 |
| R4 | 链接跟随地址 | 配对链接 = 选定地址 + `/remote-control/pair#<pairId>:<code>`；**局域网地址补网关端口，公网地址按填写的原样使用**；切换地址不需要重新生成配对码 |
| R5 | 配置持久化 | 接入地址写进 `devices.json` 的 settings，重启后保留；旧文件缺字段时按默认值补齐 |
| R6 | 诚实提示 | 选局域网且地址是回环、或选公网时，面板给出对应说明（公网需自备端口映射/TLS 反代），不再假装链接一定可达 |

### 明确不在范围内

- **可达性探测/健康检查**（用户明确：不用考虑）。不 ping、不探活、不显示"可达"结论。
- 内置公网穿透（frp/cloudflared 等）、DDNS 自动更新。地址由用户自己维护。
- 改变网关绑定地址（仍 `0.0.0.0`）或让网关只绑定某个网卡。
- 二维码（仍在 `prd.md` D2 的待办里）。
- 按设备能力白名单。

## 验收标准

1. 面板打开后在 1024×700 与 601×1731 两个视口下都**完整可见**，不出现裁切；侧栏折叠（rail）状态下同样成立。
2. `Esc` 与关闭按钮都能关闭；**点击遮罩不关闭**；关闭后焦点回到「设备与审计」按钮；打开时焦点落在面板内。
3. 局域网下拉列出本机所有非回环、非 link-local 的 IPv4，带网卡备注；默认选中第一条私网地址；选中后链接主机名立即变化。
4. 公网地址支持至少 3 条并存：可新增、可删除、可切换；非法输入（带路径/查询/非法端口/空串）被拒并给出可读错误，不写盘。
5. 配对链接格式：`http(s)://<地址>[:端口]/remote-control/pair#<pairId>:<code>`；地址里写死的端口永远优先；公网模式**不补**网关端口（`https://host` 就是 443，由用户的反代决定），局域网模式补上网关端口；**切换地址不会作废当前配对码**。
6. 地址变更**不需要重启**（响应里 `requiresReload` 只为开关/端口置真）；旧行为（开关、端口、吊销、审计）不受影响。
7. 关闭远程接入时面板行为与现在一致，不生成链接。
8. `npm test` 全绿（现有 486 + 新增），`npm run check:syntax` 通过。

## 关键约束

1. **零运行时依赖**不变（`tests/package.test.mjs` 守着）。
2. 客户端半边仍然是「单入口 + `factory(require)`」，可用 `react-dom` 的 `createPortal`（已在客户端 baseline 白名单内）。
3. 管理 API 仍然只服务回环；新增字段不新增端点外泄面；公网地址只是**显示用字符串**，不参与任何服务端决策（除了生成链接）。
4. 地址是**显示层事实**：写错地址不会让网关拒绝服务，也不会影响已配对设备——宁可链接不可用，也不要把「地址配置」变成新的鉴权因子。

## 已定稿的决策

| # | 问题 | 决策 |
|---|---|---|
| D1 | 面板形态 | 居中模态弹窗，遮罩点击**不**关闭 |
| D2 | 局域网 IP 的用途 | 只用于生成链接与二维码，**不改网关绑定** |
| D3 | 公网口径 | 用户自行配置地址（可多条），**不做可达性探测、不做穿透** |
| D4 | 生效方式 | 地址改完立即生效（只影响链接拼接），不重启 |
