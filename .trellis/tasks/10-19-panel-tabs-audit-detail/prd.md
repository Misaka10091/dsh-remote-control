# 面板分 Tab 与审计明细（含动作筛选）

## 背景

面板在 2026-10-19 的两次改动后变成「640px 宽、单列长滚动」：接入（开关/端口）、接入地址、
添加设备（二维码/配对码/链接）、已授权设备、审计（概览 + 导出）挤在一条滚动里。真机截图显示
打开面板要先滚过两屏设置才能看到二维码，而二维码恰恰是这个面板最常被打开的理由。

同时审计只有「计数 + 导出 JSONL」：想确认「刚才那台手机连过没有」，必须导出文件再自己 grep。
`api.js` 的既有限制是「面板不渲染事件详情，导出是唯一携带细节的路径」——这条限制当初是为了
不把审计做成日志浏览器，但它把最常用的确认动作推给了外部工具。

## 目标

1. 面板拆成 4 个 tab，每个 tab 的内容一屏放得下，**打开即看到最常用的那个**。
2. 分 tab 后仍能「一眼看到当前状态」：头部常驻一条状态条（监听端口 / 连接数 / 设备数）。
3. 审计 tab 提供最近事件明细：默认 50 条、加载更多、按动作筛选。
4. 明细读取路径**沿用写入时的字段白名单**，界面里不可能出现消息正文、工具参数、令牌或 Cookie。

## 范围

| # | 能力 | 说明 |
|---|---|---|
| R1 | 四个 tab | `配对` / `接入` / `设备` / `审计`；`role="tablist"`，方向键 + Home/End 切换，`aria-selected` 与 `tabpanel` 关联 |
| R2 | 自适应默认 tab | 远程接入已开启且正在监听 → 默认 `配对`；否则默认 `接入`（还没开就没有码可配） |
| R3 | 常驻状态条 | 头部标题下一条：`监听 3090 · 0 条连接 · 2 台设备`；未启用时 `远程接入未启用`。任何 tab 都可见 |
| R4 | 审计明细端点 | `GET /remote-control/api/audit/events?limit=&before=&action=`，仅回环；返回 `{ events, nextBefore }`，按时间倒序，`limit` 默认 50、上限 200 |
| R5 | 明细列表 | 时间（跨天显示日期，同日只显示 `HH:MM:SS`）、动作、设备、来源 IP；「加载更多」按钮翻页（不做无限滚动） |
| R6 | 动作筛选 | 下拉：全部 + 已知动作集合；筛选**在宿主侧生效**（否则分页会漏），未知动作值 → 400 |
| R7 | 状态与空态 | 明细加载中、无记录、加载失败（区分网络/403/服务端）三种状态各有明确文案与动作 |

### 明确不在范围内

- 不做日期范围选择、不做到「日志浏览器」级别的搜索（PRD 原决策不变：默认只做最近事件）。
- 不做实时推送/自动刷新明细（保持「点一次看一次」，避免面板变成 tail）。
- 不改审计的写入格式、保留策略与导出格式。
- 不把 `meta` 里的自由文本渲染到界面（见约束 2）。
- 不改 tab 之外的信息架构（接入/地址/设备的字段与行为保持不变）。

## 验收标准

1. 面板打开后显示单一一屏 tab 内容；在 1024×700 与 601×1731 下都不出现页面级滚动（`drc-body` 内部滚动可有，且只有一层）。
2. `role="tablist"` + 4 个 `role="tab"`；`aria-selected` 唯一为真；`Left/Right/Home/End` 可切换且焦点跟随；被选中的 tab 关联到 `role="tabpanel"` 的区域（`aria-controls`/`aria-labelledby` 双向）。
3. 默认 tab 符合 R2：接入开启且监听中 → `配对`；否则 `接入`；关闭面板再打开会按当时状态重新判定（不记忆上次 tab）。
4. 状态条在任何 tab 都显示与 `/state` 一致的监听端口、连接数、设备数；未启用时显示「远程接入未启用」。
5. 审计 tab：首次进入拉取 50 条；点「加载更多」按 `before` 游标追加且不与已有条目重复；按钮在 `nextBefore === null` 时消失并显示「没有更多了」。
6. 动作筛选在宿主侧过滤：选「配对」后返回的每一条 `event` 都是 `pair`，且分页仍能连续翻完；未知 `action` → `400 admin/invalid-argument`（不写盘、不影响审计文件）。
7. 明细里**只**出现 `ts` / `event` / `deviceId` / `ip`；构造一条含 `meta: { text: "秘密" }` 的审计记录（手工写入文件），界面不渲染 "秘密"，接口响应里也不含该键。
8. 端点仅回环：从非回环 socket 或非回环 `Host` 访问 → 403（沿用 `guard`），网关前缀拒绝不变。
9. `npm test` 全绿（现有 559 + 新增），`npm run check:syntax` 通过，`npm pack --dry-run` 仍是 31 个文件。

## 关键约束

1. **零运行时依赖**、客户端单入口、`apply` 不抛——沿用既有红线。
2. **隐私边界不变**：写入时 `audit.js` 已拒绝消息正文/工具参数/令牌/Cookie 进入文件；读取路径必须**再按同一白名单投影一次**，防止手改过的文件把额外键喂给界面（防御性，不是重复劳动）。
3. 明细端点与其它管理 API 一样仅回环，且不走网关前缀。
4. tab 切换不得产生跨挂载状态（关闭面板即重置），也不得在切 tab 时丢弃正在进行的操作状态（例如配对码倒计时仍在跑）。
5. 分页游标用 `ts`（毫秒）+ 同毫秒内的稳定序号，避免同一时间戳的两条记录被翻页吞掉或重复。

## 已定稿的决策

| # | 问题 | 决策 |
|---|---|---|
| D1 | Tab 数量与划分 | 4 个：配对 / 接入 / 设备 / 审计 |
| D2 | 默认 tab | 按「能不能立刻配」自适应，不记忆上次 |
| D3 | 明细粒度 | 最近 50 条 + 加载更多 + 动作筛选；不做日期范围 |
| D4 | 筛选位置 | 宿主侧（分页正确性），非法动作 400 |
| D5 | 明细字段 | 仅 `ts` / `event` / `deviceId` / `ip`，永不渲染 `meta` |
